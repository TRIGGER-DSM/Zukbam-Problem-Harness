# 문제 품질 체크리스트 (초안)

- 작성일: 2026-10-12 · 상태: 사용자 확인. 변경 제안 C1~C6 반영 완료
- 근거: `01-polygon-testlib.md`(R1), `02-icpc-kattis.md`(R2), `03-korean-postmortems-llm.md`(R3). 괄호 안 번호는 각 문서의 항목 번호
- 확인 방법
  - **[스크립트]**: 결정적으로 판정 가능. `scripts/`에 넣는다
  - **[AI]**: AI가 찾고 사람에게 보여준다. 판정은 하지 않는다
  - **[사람]**: 사람만 판단할 수 있다

## 리서치에서 나온 큰 결론 4가지

1. **품질 판단은 AI에게 맡기면 안 된다.** 문제 품질 평가에서 LLM과 사람의 상관은 0.07, 사람끼리는 0.71이었다 (R3-23). AI는 근거를 모으고, 판정은 스크립트나 사람이 한다. 지금 원칙과 같은 방향이다.
2. **AI는 "특정 오답을 떨어뜨리는 TC"를 잘 못 만든다.** 사람 93%, LLM 37~44%, 시간 초과 유형은 21% (R3-22). 그래서 랜덤 TC를 많이 만드는 것보다, **오답 풀이를 먼저 구체적으로 쓰고 그걸 떨어뜨리는 generator를 만드는 방식**이 필요하다 (R1-12, R3-19).
3. **brute-force 대조만으로는 부족하다.** 대조를 했어도 정해가 틀린 사례가 있다 (R3-13). 정해가 왜 맞는지 설명하는 문서(풀이 근거)를 따로 둬야 한다 (R3-16).
4. **TC가 약하면 틀린 코드가 대량으로 통과한다.** 기존 데이터셋에서 틀린 코드 통과율이 30~90%였다 (R3-18, R3-19). 3번(testcheck)이 필요한 이유다.

| S9 | 지문의 예제와 `examples/` 파일이 같다 | [스크립트] | R2-28 |

| S11 | EOF로 끝나는 입력, 공백 포함 문자열 입력을 피한다 | [AI] | R3-2 |
| S12 | 출제자가 아닌 사람이 지문만 읽고 이해할 수 있다 | [AI] blind-solver 해석 비교 → [사람] | R2-28, R3-10 |
