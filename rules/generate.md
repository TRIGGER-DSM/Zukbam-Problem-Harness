# 문제 생성 기준 (1번)

`test-problem-maker-generate`가 후보를 만들고 제약을 정할 때 쓴다. 티어는 solved.ac 기준이다.
아래 "티어별 요구"는 출발점이다. 실제 판단은 `refs/<티어 묶음>.md`의 실제 문제 분석과 맞춰 본다.

## 티어별 요구

| 티어 | 풀이에 필요한 것 | 흔한 예 |
|---|---|---|
| 브론즈 | 지문을 그대로 옮기는 구현. 반복문, 조건문, 간단한 산수 | 시뮬레이션, 최댓값·합 구하기 |
| 실버 | 표준 기법 하나. 관찰은 없거나 하나 | 정렬, 누적 합, BFS/DFS, 이분 탐색, 1차원 DP, 간단한 그리디 |
| 골드 | 표준 기법 하나에 관찰 하나, 또는 기법 둘의 조합 | 다익스트라, 위상 정렬, 배낭 DP, 분리 집합, 투 포인터, 정당성 증명이 필요한 그리디 |
| 플래티넘 | 고급 자료구조·기법, 또는 골드 기법에 어려운 관찰 | 세그먼트 트리, LCA, 비트마스크 DP, 최대 유량, 강한 연결 요소 |
| 다이아 | 고급 기법의 조합과 핵심 관찰 둘 이상, 또는 최적화 | 느린 갱신 세그먼트 트리, HLD, 오프라인 쿼리, DP 최적화, 분할 정복 |

- 한 티어 안에서 5 → 1로 갈수록 관찰이 더 숨어 있거나, 구현할 경우가 많아지거나, 제약이 빡빡해진다.
- 지문 이야기가 풀이를 그대로 알려 주면 티어가 내려간다 (예: "누적 합을 구하시오"). 이야기 속에 기법을 숨긴다.
- 막아야 할 쉬운 풀이를 제약으로 막지 못하면 티어가 내려간다.

## 제약 정하기

시간 제한 1초, C++ 기준으로 1초에 단순 연산 약 10⁸번이다. **Python 정답(`sol/main.py`)도 같은 시간 제한을 통과해야 하므로** 의도 풀이의 연산 수를 약 10⁷ 이하로 맞춘다. 맞출 수 없으면 시간 제한을 늘리거나 N을 줄인다.

| 의도 복잡도 | N의 대략적인 최대 |
|---|---|
| O(N) | 10⁶ |
| O(N log N) | 2 × 10⁵ |
| O(N √N) | 5 × 10⁴ |
| O(N²) | 3 × 10³ |
| O(N³) | 200 |
| O(2^N · N) | 18 |
| O(N!) | 9 |

- 막아야 할 쉬운 풀이가 최대 입력에서 의도 풀이보다 **최소 10배** 느려야 시간 제한으로 가를 수 있다. 차이가 그보다 작으면 (예: O(N log N)과 O(N log² N)) 시간 제한으로 막지 않는다.
- 값의 범위는 답의 최대 크기를 계산해 정한다. 32비트를 넘으면 지문에 64비트가 필요하다는 것이 드러나게 예제나 범위를 둔다 (일부러 숨기는 것도 출제 의도일 수 있으니 설계 결정에 적는다).
- 입력이 10⁶개를 넘으면 C++ `cin` 속도 차이가 판정을 가를 수 있다. 피한다.

## 검증할 수 있는 문제만 낸다

- 작은 입력(N이 10 안팎)에서 완전 탐색으로 답을 구할 수 있어야 한다. 그래야 brute-force 대조가 된다.
- 답이 하나로 정해지게 한다. 여러 개를 허용하면 `checker.py`가 필요하고 검증이 약해진다.
- 실수 출력은 피한다. 꼭 필요하면 허용 오차를 지문에 적고 `checker.py`를 쓴다.

## 난이도 신호

스크립트로 티어를 판정할 수는 없다. 아래는 **신호**로만 보고하고, 판정처럼 쓰지 않는다.

| 신호 | 뜻 |
|---|---|
| fast-solver(지문만 본 두 번째 정답)가 "못 풂" | 목표보다 어렵거나 지문에 필요한 정보가 없다 |
| Haiku가 쓴 풀이(`sol/probe-haiku.cpp`)가 모든 TC 통과, 목표가 플래티넘 이상 | 목표보다 쉬울 수 있다 |
| Haiku가 못 풀거나 실패, 목표가 실버 이하 | 목표보다 어렵거나 지문이 부족할 수 있다 |
| 막아야 할 쉬운 풀이가 시간 초과를 받지 못함 | 티어가 내려간다. 제약을 고친다 |

## 실제 문제 참고

- `refs/<티어 묶음>.md`: 실제 문제를 분석한 자료. 티어별 태그 통계, 대표 문제와 그 특징(제약, 관찰, 비틀기, 막히는 쉬운 풀이, 지문 특징), 요약. 위 "티어별 요구"보다 이 자료가 우선이다.
- 대표 문제의 내용이 필요하면 인터넷에서 검색해 지문과 풀이를 읽는다 ("백준 <번호> <제목>"). 백준은 2026년에 서비스를 종료해 원문 페이지는 없다. 블로그 풀이나 지문을 옮겨 둔 곳을 읽는다. 내용이 틀릴 수 있으니 "이 티어 문제가 어떤 관찰을 요구하는가"를 보는 데만 쓴다.
- 읽은 지문의 문장, 이야기, 예제를 가져오지 않는다. 새 문제는 새로 쓴다.
