# 문제 품질 원칙

모든 스킬은 작업 전에 이 파일을 읽는다. 문제 폴더 형식은 `rules/package.md`, 항목별 근거는 `docs/research/checklist.md`.

## 판정
1. **판정은 스크립트만 내린다.** 통과·오답·시간 초과는 `scripts/` 출력이 말한 것만 사실로 보고한다. 출력은 고치지 않고 그대로 `report.md`에 붙인다.
2. **AI가 손으로 쓴 `.out`은 쓰지 않는다.** `.out`은 정답 풀이를 실행해서 만든다. 지문의 예제 출력은 출제자가 준 것이므로 예외다.
3. **풀이 하나만 믿지 않는다.** 정답 풀이는 지문만 보고 따로 쓴 brute-force와 작은 랜덤 입력으로 대조한다. 두 풀이가 자주 갈리면 코드보다 지문이 모호한지 먼저 의심한다.
4. **정답이 왜 맞는지 `sol/README.md`에 적는다.** brute-force 대조를 통과해도 정답이 틀린 사례가 있다.
5. **TC는 랜덤으로 많이 만드는 것보다 오답을 떨어뜨리는 것이 중요하다.** 떨어뜨릴 오답 풀이를 먼저 구체적으로 쓰고, 그것을 떨어뜨리는 TC를 만든다. AI는 이 일을 특히 못하므로(사람 93%, LLM 약 40%) 스크립트로 탈락을 확인한다.
6. **validator와 generator는 서로 다른 에이전트가 쓴다.** 같은 쪽이 쓰면 같은 오해를 공유한다. 같은 이유로 떨어뜨릴 풀이와 TC도 다른 쪽이 쓰고, 정답을 한 곳씩 바꾼 변이 풀이(`scripts/mutate.py`)로 사람이 생각 못 한 실수도 확인한다.

## 지문
7. **모호한 지문을 내보내지 않는다.** 경계값(N=0, N=1, 같은 값, 음수), 출력 형식, 정답이 여러 개일 때의 처리가 지문에 적혀 있어야 한다.
8. **출제 의도는 AI가 정하지 않는다.** 오탈자·형식은 [수정]으로 바로 고치고, 의도가 걸린 것("N=0이 가능한가?")은 [질문]으로 출제자에게 묻는다.
9. **사용자가 준 `.out`과 정답 풀이가 다르면 어느 쪽이 맞는지 정하지 않는다.** 결과가 갈리는 가장 작은 TC와 양쪽 출력을 보여주고 묻는다.

## 시간 제한
10. **시간 제한은 하나로 둔다.** Python 정답(`sol/main.py`)은 통과하고, 의도하지 않은 느린 C++ 풀이(`sol/time_limit_exceeded/`)는 넘지 못하는 값이어야 한다. 공식은 `rules/package.md`의 "시간 제한".
11. 그런 값이 없으면 입력 크기를 키워 차이를 벌려 본다. 그래도 없으면 [질문]으로 출제자에게 알린다. 시간 복잡도 차이가 작은 문제(예: O(N log N)과 O(N log² N))는 대개 불가능하다.
12. 측정값은 이 컴퓨터 기준이다. `report.md`에 그 사실을 적는다. 다른 무거운 작업(여러 harness 동시 실행, 빌드)과 함께 재면 CPU 시간도 두 배 넘게 부풀 수 있다. `verdicts.py`는 정답 시간을 여러 번 재서 최솟값을 쓰지만, 시간 제한을 정할 때는 한가할 때 다시 잰다.

## 보고
13. 끝 보고에는 몇 개 입력으로 대조했는지, 결과가 갈린 적이 있었는지, 사람이 확인해야 할 것을 적는다. 마지막 검토는 사람이 한다.
