# test-problem-maker-generate

먼저 `rules/principles.md`, `rules/package.md`, `rules/generate.md`를 읽는다. `P`는 문제 폴더다.
여기서 만든 문제는 끝나면 start로 돌아가 지문 검토 → TC 생성 → TC 검증을 그대로 거친다. 여기서 검증을 대신하지 않는다.

## 1. 요청 정리
풀이 방식(여러 개일 수 있음), 키워드(이야기 소재), 목표 티어, 개수, 변형할 기존 문제(있으면)를 뽑는다.
- 티어가 없으면 [질문]. 키워드가 없으면 이야기는 자유롭게 정한다.
- 여러 개면 문제마다 2~6절을 따로 한다.

## 2. 실제 문제 참고
목표 티어의 분석 자료 `refs/<티어 묶음>.md`(브론즈·실버·골드·플래티넘·다이아)를 읽는다.
- **요약**: 이 티어 문제가 보통 요구하는 것 (관찰 수, 제약 크기, 비틀기 방식, 지문 모양). 후보는 이 요약에 맞춘다.
- **태그 통계**: 목표 세부 티어(예: 실버 3) 줄에서 이 방식이 얼마나 흔한지, 무엇과 같이 붙는지 본다. 이 방식이 이 티어에 거의 없으면 가까운 티어를 제안하는 [질문]을 한다 (일괄이면 그대로 만들고 그 사실을 적는다).
- **대표 문제**: 같은 방식이거나 같은 세부 티어인 문제의 "문제별 특징"을 읽는다. 제약, 관찰 수, 비틀기, 막히는 쉬운 풀이를 후보의 기준으로 삼는다. 이 문제들은 이미 유명하므로 이야기만 바꾼 후보가 되면 안 된다.
- 자료가 부족하면 대표 문제를 인터넷에서 더 찾아 읽는다 ("백준 <번호> <제목> 풀이"). 출처가 "기억"인 항목은 참고만 한다.
- 실제 문제의 지문 문장을 가져오거나 흉내 내지 않는다.

## 3. 후보 3개 → 고르기
`rules/generate.md`의 "티어별 요구"에 맞는 후보 3개를 만든다. 후보마다:
- 이야기 한 줄 (키워드 사용)
- 핵심 풀이와 복잡도, 필요한 관찰
- 이 티어인 근거 (2절 결과와 "티어별 요구"를 인용)
- 막아야 할 쉬운 풀이와 그것을 막는 제약 (막지 못하면 난이도가 내려간다)
- 가장 비슷한 유명 문제와 다른 점
- 작은 입력에서 완전 탐색(brute-force)이 가능한지. 불가능한 후보는 내지 않는다 (검증할 수 없다)

**이미 있는 문제인지 확인한다.** 후보마다 이야기를 뺀 핵심(입력 구조, 구하는 것, 의도 풀이)으로 인터넷을 검색한다 (예: "가중치 완료 시간 합 최소 정렬 백준"). 이야기만 다르고 입력·출력·풀이가 같은 문제가 있으면 그 후보는 버리거나, 풀이가 달라지게 비튼다 (조건 추가, 구하는 것 변경). 찾은 비슷한 문제는 후보에 적는다. 검색할 수 없는 환경이면 그렇다고 적는다.

사용자에게 [질문]으로 고르게 한다. 사용자가 "알아서", "한꺼번에 여러 개"처럼 맡겼으면 가장 좋은 후보를 고르고 이유를 `state.md`에 적는다.

## 4. 지문
`problem.md` 템플릿 순서(문제 / 입력 / 출력 / 제한 / 예제 설명)로 쓴다.
- 제약은 `rules/generate.md`의 "제약 정하기"로 정한다. 의도 풀이(C++과 Python 모두)는 통과하고 3절의 쉬운 풀이는 시간 초과가 나는 크기.
- **경계 결정을 지문에 모두 적는다**: N=1, 같은 값, 맞닿음·포함, 답이 없을 때, 답이 여러 개일 때 (`docs/research/checklist.md`의 S4, S5). 정한 내용은 `state.md`의 "설계 결정"에도 적는다.
- 답이 여러 개인 문제는 피한다. 꼭 필요하면 `checker.py`를 쓴다.
- 표기는 체크리스트 S10을 따른다.

## 5. 정답과 예제
1. `sol/main.cpp`에 의도 풀이를 쓴다. `sol/README.md`에 아이디어, 왜 맞는지, 복잡도, 막아야 할 쉬운 풀이를 쓴다.
2. 예제 입력 2~3개를 `examples/N.in`에 쓴다. 손으로 따라갈 수 있게 작게, 출력 유형마다 하나 (답 없음 등). **`.out`은 쓰지 않는다.**
3. `meta.json`: `mode` 1, `method`, `keywords`, `difficulty`(목표 티어), `time_limit_ms` 0 (testgen이 정한다).
4. `python3 scripts/make_outputs.py P` → 예제 `.out`을 정답 실행으로 만든다.
5. 만든 출력을 보고 `problem.md`의 예제 설명을 쓴다. 설명의 계산은 출력과 같아야 한다.

## 6. 넘기기
`state.md`에 고른 후보, 설계 결정, 다음 단계(statement-review)를 적고 start로 돌아간다.
이후 지문 검토에서 나온 [질문] 중 "설계 결정"에 이미 있는 것은 그 결정대로 지문에 반영하고([수정]), 설계에 없는 것만 사용자에게 묻는다.
