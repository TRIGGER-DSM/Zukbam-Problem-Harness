# test-problem-maker-statement-review

먼저 `rules/principles.md`를 읽는다. 항목 번호(S1 등)는 `docs/research/checklist.md`의 것이다.
**AI는 지문 품질을 판정하지 않는다** (LLM과 사람의 품질 판단 상관이 0.07이었다). 근거를 찾아 보여주고, 의도가 걸린 것은 출제자가 정한다.

## 1. 독립적으로 읽히는지 확인 (S12)
`test-problem-maker-blind-solver`를 **두 번 따로** 호출한다 (서로 결과를 모르게). 각자 `sol/brute.cpp`를 쓰므로 두 번째는 `sol/blind-2.cpp`에 쓰게 경로를 지정한다 (verdicts.py가 돌리지 않는 위치. 작은 입력용이라 큰 TC에서는 느리다).
- 두 에이전트가 보고한 "해석이 갈리는 곳"을 모은다.
- 두 풀이를 작은 랜덤 입력으로 대조한다. 생성기가 없으면 `gen/gen.py`를 먼저 쓴다: `python3 gen/gen.py <인자...> <seed>`가 입력 하나를 표준 출력에 쓰고, 같은 인자면 같은 출력(`random.Random(" ".join(sys.argv[1:]))`). 맨 위 docstring에 인자 설명.
  `python3 scripts/stress.py P --gen "<작은 입력 {seed}>" --a sol/brute.cpp --b sol/blind-2.cpp --count 200`
  불일치가 나오면 그 입력에서 지문이 두 가지로 읽힌다는 뜻이다. 가장 작은 입력을 [질문]의 근거로 쓴다.
- 예제를 통과하지 못한 풀이가 있으면 지문과 예제가 어긋날 수 있다 (S9).

## 2. 체크리스트로 읽기
`problem.md`를 아래 항목으로 하나씩 본다. 찾은 것마다 지문의 해당 문장을 인용한다.

| 항목 | 볼 것 |
|---|---|
| S1 | 입력의 모든 변수에 범위가 있는가 (부등식, 변수가 처음 나오는 곳에) |
| S3 | 줄 구성과 구분 방식이 명시돼 있는가 ("첫째 줄에", "공백을 사이에 두고") |
| S4 | 출력 형식: 답이 여러 개일 때, 답이 없을 때, 실수 오차, 대소문자 |
| S5 | 경계 상황: N=1, 같은 값, 맞닿음/포함 여부, 도달 불가, 빈 결과 |
| S6 | 지문이 보장하지 않는 성질(정렬, 연결, 서로 다름) — testgen에 반례 TC로 넘긴다 |
| S7 | 정의 전에 쓰는 것, 같은 이름이 두 대상을 가리키는 것 |
| S8 | 예제 2개 이상, 출력 유형마다 하나, 손으로 따라갈 수 있는 작은 예제 |
| S9 | 예제 설명의 계산이 예제 출력과 같은가 (직접 계산해 본다) |
| S10 | 표기: '자연수' 대신 '양의 정수', ≤ ≥ ≠ ×, 번역체("보장된다"), 1부터 인덱스. 줄은 "첫째 줄", "i째 줄"이 맞는 표기다(UCPC 컨벤션). 이 표에 없는 문체 취향으로는 [수정]하지 않는다 |
| S11 | EOF로 끝나는 입력, 공백이 들어간 문자열 입력 |

같은 정보가 두 곳(예: 문제 절과 출력 절)에 있으면 서로 같은지 확인한다.

## 3. 지적을 나눠 정리
- **[수정]**: 의도와 상관없는 것 (오탈자, 표기 규칙, 누락된 "공백을 사이에 두고"). 바로 고치고 바꾼 문장을 기록한다.
- **[질문]**: 출제 의도가 걸린 것 (범위, 경계 상황 처리, 해석이 갈리는 문장). 고치지 않는다. 질문마다 근거(인용, 갈리는 입력)와 가능한 선택지를 붙인다.
- **[TC로 넘김]**: S6처럼 지문은 괜찮지만 TC가 반드시 다뤄야 할 것.

출제자의 답을 받으면 지문에 반영하고 1~3을 다시 한다. 최대 3회. 그래도 [질문]이 남으면 남은 채로 보고한다.

## 4. 끝
`report.md`에 [수정] 목록(전/후 문장), [질문]과 답, [TC로 넘김] 목록, blind 풀이 대조 결과(스크립트 출력 그대로)를 적는다. `state.md`의 `stage`를 `reviewed`로 바꾼다.
